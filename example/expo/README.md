# Ströer SDK Expo example

An Expo app (Continuous Native Generation / `expo prebuild`) that integrates
`react-native-stroeer-sdk` 1.0.0 on **Expo SDK 55 / React Native 0.83.10** (New Architecture).
It shows:

- a banner ad, with local and global custom targeting,
- an interstitial ad and a rewarded ad, shown as soon as they are loaded,
- an on-screen event log of all ad callbacks (plus a `ToastAndroid` on Android).

The app runs out of the box with a Ströer test configuration. Use it as a reference for your own
integration; the full API is described in the [integration manual](../../docs/1.0/Integration.md).

The bare React Native version of this app lives in [`../react-native`](../react-native/README.md).
The app code is the same; only the native setup differs (a config plugin instead of edited native
projects).

## Requirements

- Node 20.19.4+ and npm (use npm/npx; Yarn is not set up in this project)
- Android: JDK 17+, Android SDK, an emulator or device
- iOS: Xcode with an iOS 15.1+ simulator or device, CocoaPods
- A Ströer SDK compatible Expo version: Expo SDK 55 or later (the SDK requires React Native
  0.82.1+; Expo SDK 54 ships React Native 0.81)

### Expo Go is not supported

The SDK contains custom native code (native modules and a Fabric view), which Expo Go does not
include. Use a development build: this project includes `expo-dev-client`, so
`npx expo run:android` / `npx expo run:ios` produce one.

## Install

```sh
npm install react-native-stroeer-sdk
npm install
```

The SDK is installed from the npm registry
([`react-native-stroeer-sdk`](https://www.npmjs.com/package/react-native-stroeer-sdk)).

## Run on Android

```sh
npx expo prebuild --platform android      # generates android/
npx expo run:android                      # builds, installs and starts Metro
```

Or build the APK yourself: `cd android && ./gradlew assembleDebug`, install it, then
`npx expo start --dev-client`.

The `android/` and `ios/` folders are generated by `expo prebuild` and are not committed. Run
`npx expo prebuild --clean` again after changing `app.json` or the config plugin.

## Run on iOS

```sh
npx expo prebuild --platform ios          # generates ios/ and runs pod install
npx expo run:ios
```

Or open `ios/StroeerExampleExpo.xcworkspace` in Xcode. Select your own signing team in Xcode before
running on a device.

## Test configuration

The app uses Ströer test values. Replace them with the values from your Ströer account manager
before you go live.

| Value | Test value | File |
| --- | --- | --- |
| Application name | `appTest` | `App.tsx` (`APPLICATION_NAME`) |
| Banner slot | `b2` | `App.tsx` (`BANNER_SLOT`) |
| Interstitial slot | `interstitial` | `App.tsx` (`INTERSTITIAL_SLOT`) |
| Rewarded slot | `rewarded` | `App.tsx` (`REWARDED_SLOT`) |
| Google Mobile Ads app ID (Android) | `ca-app-pub-3940256099942544~3347511713` | `app.json` (`androidAdMobAppId`) |
| Google Mobile Ads app ID (iOS) | `ca-app-pub-3940256099942544~1458002511` | `app.json` (`iosAdMobAppId`) |

The Google Mobile Ads app IDs are Google's public test IDs. The app crashes at startup without an
app ID, so always set your own, then run `npx expo prebuild --clean`.

## Using the app

- **Reload Banner** remounts the banner, which loads a new ad.
- **Interstitial** / **Rewarded** load the ad and show it as soon as it is loaded.

The buttons are disabled (gray) until the SDK has been initialized, and while an interstitial or rewarded
ad is loading. Every ad callback is written to the **Events** log below the buttons.

### Where to look in the code

| What | Where |
| --- | --- |
| SDK initialization (`setApplicationName`, debug mode, global targeting, content URL) | `App.tsx`, init `useEffect` |
| Banner with local targeting and listeners | `App.tsx`, `<StroeerBannerAd>` |
| Interstitial and rewarded ads | `App.tsx`, `useStroeerInterstitial` / `useStroeerRewarded` |
| Event log and toasts | `src/useNotifier.ts` |
| Native configuration | `app.json`, `plugins/withStroeerSdk.js` |

## Debug panel

In debug builds (`__DEV__`) the app calls `enableDebugMode()` and `enableInspectionMode()`, after
`setApplicationName()`. Press and hold an ad with two or three fingers for three to four seconds,
then tap the debug label in the top-left corner. Double-tap the panel to copy its contents. Never
enable inspection mode in production.

## Project setup

Expo generates the native projects, so all native configuration lives in `app.json`. Apply the same
configuration to your own app.

### Config plugin

`plugins/withStroeerSdk.js` is a local config plugin (options in `app.json`). During
`expo prebuild` it:

- Android: adds the `com.google.android.gms.ads.APPLICATION_ID` meta-data to `<application>` in
  `AndroidManifest.xml`.
- iOS: adds `GADApplicationIdentifier` to `Info.plist`, and this line to the `Podfile`:
  `pod 'StroeerSDK', :subspecs => ['Core']`. Add the `Consent` subspec only if you use the SDK's
  consent module.

Copy the plugin into your project and register it in `app.json` with your own AdMob app IDs.

## Troubleshooting

- **Expo Go fails or reports missing native modules**: use the development build
  (`npx expo run:android` / `npx expo run:ios`).
- **Gradle cannot resolve `com.stroeer.ads`**: check `extraMavenRepos` in `app.json`, then run
  `npx expo prebuild --clean`.
- **Changes to `app.json` have no effect**: run `npx expo prebuild --clean` to regenerate the native
  projects.
- **"AsyncStorage is null" or another app's code appears**: another Metro server is running on port
  8081. Stop it or use another port: `npx expo run:android --port 8082`, or
  `npx expo start --dev-client --port 8082`.
- **Stale builds**: `../clean-build.sh expo [android|ios]` removes `node_modules` and the generated
  native projects, regenerates them and builds the app. Run it with `--help` for the options.
